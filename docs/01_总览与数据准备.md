# Unreal Engine 5.8 Developer RAG 教学文档

本教程介绍如何构建一个面向 Unreal Engine 5.8 的开发者 RAG（Retrieval-Augmented Generation）系统。

目标是让 AI coding agent 能够检索 UE5.8 官方文档、引擎 C++ 源码、项目源码、配置、插件和 Blueprint 资产。

## 1. RAG 是什么

RAG 不等于单独调用一个大模型。典型链路如下：

```text
原始文档 / 源码 / 项目 / Blueprint
        ↓
采集 → 解析 → 语义切块
        ↓
Embedding 向量 + Lexical 关键词索引
        ↓
向量检索 + 关键词检索
        ↓
RRF 混合排序 → Reranker 重排
        ↓
MCP 工具 / Web 服务 / LLM 回答
```

本项目的检索结果本身是上下文。若要实现“提问后自动生成完整答案”，还需要另外接入 LLM API；Embedding 和 LLM 回答是两个不同的环节。

## 2. 环境准备

```powershell
Set-Location "E:\UE5.8 RAG"
python --version
```

建议使用 Python 3.11 或更高版本。安装依赖：

```powershell
python -m pip install -e ".[dev]"
```

主要依赖：

- `pydantic`：数据模型校验
- `tree-sitter-cpp`：C++ 语法解析
- `sentence-transformers`：本地 Embedding
- `qdrant-client`：向量索引
- `mcp`：MCP 服务
- `pytest`：自动化测试

## 3. 配置文件

主要配置位于 `config/`：

| 文件 | 作用 |
| --- | --- |
| `ue58.yaml` | UE 版本、引擎路径和数据目录 |
| `crawler.yaml` | 官方文档抓取参数 |
| `docs_parser.yaml` | HTML 文档解析参数 |
| `docs_chunker.yaml` | 文档切块参数 |
| `engine_parser.yaml` | C++ 解析参数 |
| `engine_chunker.yaml` | C++ 切块参数 |
| `embedding.yaml` | Embedding 模型、设备、批量和输出路径 |
| `qdrant.yaml` | Qdrant 集合和存储路径 |
| `lexical.yaml` | SQLite FTS5 索引路径和 Top-K |
| `retrieval.yaml` | Hybrid/RRF 参数 |
| `reranker.yaml` | Reranker 模型和最终 Top-K |
| `project_scanner.yaml` | 项目扫描范围 |

当前本机的 Embedding 配置使用 CUDA：

```yaml
provider: qwen
model: Qwen/Qwen3-Embedding-0.6B
device: cuda
batch_size: 16
max_length: 2048
normalize: true
```

API Key、项目路径等机器相关信息不要提交到 Git。

## 4. 文档和源码处理

### 4.1 下载官方文档

先进行不写文件的检查：

```powershell
python scripts/ingest_docs.py --topic cpp --dry-run
```

小规模抓取：

```powershell
python scripts/ingest_docs.py --topic cpp --max-pages 10 --max-depth 1
```

### 4.2 解析 HTML

```powershell
python scripts/parse_docs.py
```

输出：

```text
data/parsed/docs/documents.jsonl
data/parsed/docs/issues.jsonl
```

### 4.3 文档切块

```powershell
python scripts/chunk_docs.py
```

输出：

```text
data/chunks/docs/chunks.jsonl
```

每个 chunk 保留标题路径、URL、UE 版本、源类型和确定性 ID。

### 4.4 扫描 Unreal Engine 源码

在 `config/ue58.yaml` 设置 `engine.root`，指向包含 `Engine/` 的目录：

```powershell
python scripts/ingest_engine.py --dry-run
python scripts/ingest_engine.py
```

### 4.5 解析 C++ 符号

完整解析：

```powershell
python scripts/parse_engine.py
```

小范围冒烟测试：

```powershell
python scripts/parse_engine.py `
  --path-contains CharacterMovementComponent `
  --limit-files 20 `
  --output work/t07_character_movement.jsonl
```

解析器以类、结构体、枚举、函数、方法、构造函数和字段为单位生成文档，并保留 `UCLASS`、`UFUNCTION`、`UPROPERTY` 等 UE 宏。

### 4.6 C++ 语义切块

```powershell
python scripts/chunk_engine.py
```

小范围切块：

```powershell
python scripts/chunk_engine.py `
  --input work/t07_character_movement.jsonl `
  --output work/t08_character_movement.jsonl
```

函数通常保持完整；过大的函数或类型会按源代码行拆分，并重复模块、类、符号和文件上下文。

## 5. 建立 Lexical 索引

Lexical 索引使用 SQLite FTS5，适合精确符号、类名、函数名、宏名、路径和源码关键词检索。

推荐使用全量重建：

```powershell
python scripts/build_lexical_index.py `
  --rebuild `
  --batch-size 2048 `
  --progress-every 100000
```

构建完成后检查数量：

```powershell
python -c "import sqlite3; c=sqlite3.connect('data/index/lexical.sqlite3'); print(c.execute('select count(*) from chunks').fetchone()[0]); print(c.execute('select count(*) from chunks_fts').fetchone()[0]); c.close()"
```

当前完整 C++ 索引约有 1,693,105 个 chunks。`--rebuild` 会先写临时数据库，成功后再原子替换目标索引。
